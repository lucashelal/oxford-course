6.2 Working with Dataframes: The NutriHeart Study

A single vector is fine for one measurement, but real research almost never stops at one measurement. A real study measures many things about the same person — their age, their diet, whether they smoke, when they joined the study. R stores this kind of data in a dataframe: a table where every row is one participant and every column is one variable.

To practice this, we will build a small, simulated dataset modeled on a real type of study in nutritional epidemiology.

6.2.1 The study context

Imagine a research team wants to understand how eating patterns relate to cardiometabolic health — that is, health related to the heart and metabolism. They design a study called the NutriHeart Study.

Research question: Among adults, is the type of diet a person follows (Mediterranean, Western, Vegan, or Keto) associated with cardiometabolic risk markers such as body mass index (BMI) and hypertension — and does the person’s physical activity level change that relationship?

To answer this, the team recruits 200 adult participants between 2020 and 2023. At enrollment, each participant answers a questionnaire and undergoes a short clinical exam. This is a cross-sectional study: everyone is measured once, at a single point in time, which lets the researchers describe patterns in the population but not prove that diet causes the outcomes.

Every variable the team collects has a reason for being there. Before writing a single line of code, it helps to know what we are about to build and why:

# Variable What it means Type
1 patient_id A unique number identifying each participant (like a folder number) Identifier
2 enrollment_date The calendar date the participant joined the study Date
3 gender Self-reported gender of the participant Categorical
4 age Age in completed years at enrollment Continuous
5 bmi Body Mass Index (kg/m²), a common marker of nutritional status Continuous
6 diet_type The dominant diet pattern the participant reports following Categorical
7 physical_activity_level Self-reported activity level: Low, Moderate, or High Categorical (ordered)
8 daily_calories Estimated average daily caloric intake (kcal), from a dietary recall Continuous
9 sugar_intake_g Estimated average daily sugar intake, in grams Continuous
10 hypertension Whether the participant has a clinical diagnosis of high blood pressure Logical (yes/no)
11 smoker Whether the participant currently smokes Logical (yes/no)
12 clinical_notes A short free-text note written by the clinician during the exam String (text)

Notice that these 12 variables cover every basic data type you will meet in R: numbers that can take any value (continuous), numbers or labels that fall into groups (categorical), dates, TRUE/FALSE values (logical), and free text (string). Real datasets are almost always this mixed — this is exactly why R needs different functions for different types of variables, which is what the rest of this chapter is about.

6.2.2 1. Loading the tools we need

We will use the tibble package to build a modern, easy-to-read dataframe (a “tibble” is just RStudio’s improved version of a dataframe). We install it once per computer, and load it once per R session.

install.packages("tibble")
library(tibble)
  • install.packages("tibble") downloads the package from the internet and installs it on your computer. You only need to run this once — after that, R remembers it.
  • library(tibble) loads the package into your current R session, making its functions (like tibble()) available to use. You need to run this every time you open a new R session.

6.2.3 2. Building the dataset, line by line

Before generating anything random, we fix R’s “randomness” with set.seed(). Computers cannot generate truly random numbers — they use a formula that looks random. set.seed() tells that formula where to start, so that everyone who runs this exact code gets the exact same “random” numbers. This is essential for reproducible research.

set.seed(123)

Now we build the dataframe itself. Each argument inside tibble() becomes one column. Read the explanation below the code slowly, matching each line back to the table above.

library(tibble)
set.seed(123)

nutriheart_data <- tibble(

  # 1. patient_id: a simple sequence from 1 to 200, one number per participant
  patient_id = 1:200,

  # 2. enrollment_date: pick 200 random dates between two limits, with repetition allowed
  enrollment_date = sample(
    seq(as.Date("2020-01-01"), as.Date("2023-12-31"), by = "day"),
    size = 200,
    replace = TRUE
  ),

  # 3. gender: pick "Male" or "Female" at random for each participant
  gender = sample(c("Male", "Female"), size = 200, replace = TRUE),

  # 4. age: pick a whole number of years between 18 and 85 for each participant
  age = sample(18:85, size = 200, replace = TRUE),

  # 5. bmi: draw from a uniform range (18.0 to 42.0), then round to 1 decimal
  bmi = round(runif(200, min = 18.0, max = 42.0), 1),

  # 6. diet_type: pick one diet label per participant, but NOT with equal chances
  diet_type = factor(
    sample(
      c("Mediterranean", "Western", "Vegan", "Keto"),
      size = 200,
      replace = TRUE,
      prob = c(0.40, 0.30, 0.15, 0.15)
    )
  ),

  # 7. physical_activity_level: an ORDERED categorical variable (Low < Moderate < High)
  physical_activity_level = factor(
    sample(c("Low", "Moderate", "High"), size = 200, replace = TRUE,
           prob = c(0.30, 0.45, 0.25)),
    levels = c("Low", "Moderate", "High"),
    ordered = TRUE
  ),

  # 8. daily_calories: draw from a normal (bell-curve) distribution around 2200 kcal
  daily_calories = round(rnorm(200, mean = 2200, sd = 450)),

  # 9. sugar_intake_g: same idea, centered on 55 grams per day
  sugar_intake_g = round(rnorm(200, mean = 55, sd = 20), 1),

  # 10. hypertension: TRUE/FALSE, but only 35% of participants are TRUE
  hypertension = sample(c(TRUE, FALSE), size = 200, replace = TRUE,
                         prob = c(0.35, 0.65)),

  # 11. smoker: TRUE/FALSE, only 20% of participants are TRUE
  smoker = sample(c(TRUE, FALSE), size = 200, replace = TRUE,
                   prob = c(0.20, 0.80)),

  # 12. clinical_notes: pick one short sentence per participant from a fixed list
  clinical_notes = sample(
    c("Patient reports fatigue.",
      "Adheres strictly to diet.",
      "Sedentary lifestyle.",
      "No recent complaints."),
    size = 200, replace = TRUE
  )
)

Let’s unpack the functions that keep reappearing above, since they do most of the work:

  • sample(x, size, replace, prob) picks values at random out of a set x. size is how many picks we want, replace = TRUE means the same value can be picked more than once (essential here, since we need 200 picks from only a handful of options), and prob optionally sets how likely each option is — without it, every option is equally likely.
  • runif(n, min, max) draws n random numbers uniformly between min and max — every value in that range is equally likely. Good for something like BMI, where we only know a plausible range.
  • rnorm(n, mean, sd) draws n random numbers from a normal (bell-curve) distribution — most values land near mean, and sd (standard deviation) controls how spread out they are. Good for something like daily calories, which tends to cluster around a typical value.
  • round(x, digits) rounds a number to a chosen number of decimal places. round(x) with no second argument rounds to a whole number.
  • factor() tells R “this is a categorical variable, not free text.” Adding levels = c(...) and ordered = TRUE, as we did for physical_activity_level, tells R the categories have a natural order (Low is less than Moderate is less than High) — this matters later for correct sorting and modeling.
  • seq(from, to, by) generates a full sequence of values — here, every single calendar day between 2020-01-01 and 2023-12-31 — which sample() then picks 200 dates out of.

6.3 Descriptive statistics by variable type

Different variable types answer different questions, so they need different summary functions. We will now go through the four families of variables in nutriheart_data and summarize each one appropriately, using $ to pull out a single column (e.g. nutriheart_data$age means “the age column inside nutriheart_data”).

6.3.1 Continuous variables (age, bmi, daily_calories, sugar_intake_g)

For continuous variables, we want to know the center of the data and how spread out it is.

mean(nutriheart_data$bmi)      # the average BMI
[1] 29.7445
median(nutriheart_data$bmi)    # the middle BMI, if all values were sorted
[1] 30.2
sd(nutriheart_data$bmi)        # standard deviation: typical distance from the mean
[1] 6.729241
range(nutriheart_data$bmi)     # smallest and largest BMI values, as one vector
[1] 18.1 41.8
summary(nutriheart_data$bmi)   # all of the above, in one call
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
  18.10   24.45   30.20   29.74   35.25   41.80

summary() is often the fastest first step: with one function call it returns the minimum, the 1st quartile (the value below which 25% of the data falls), the median, the mean, the 3rd quartile, and the maximum — a compact picture of the whole distribution.

6.3.2 Categorical variables (gender, diet_type, physical_activity_level)

For categorical variables, “average” makes no sense — instead, we want counts and proportions per group.

table(nutriheart_data$diet_type)                       # how many participants per diet

         Keto Mediterranean         Vegan       Western 
           28            83            35            54 
round(prop.table(table(nutriheart_data$diet_type)) * 100, 1)  # same thing, as percentages

         Keto Mediterranean         Vegan       Western 
         14.0          41.5          17.5          27.0
  • table(x) counts how many times each unique category appears in x.
  • prop.table(t) takes a table of counts and converts every count into a proportion of the total (values between 0 and 1). Multiplying by 100 and wrapping in round(..., 1) turns those proportions into readable percentages with one decimal place.

6.3.3 Logical variables (hypertension, smoker)

Logical variables only ever hold TRUE or FALSE. Two small tricks make them easy to summarize:

table(nutriheart_data$hypertension)          # counts of TRUE and FALSE

FALSE  TRUE 
  132    68 
mean(nutriheart_data$hypertension) * 100      # % of participants with hypertension
[1] 34

This second trick works because R secretly stores TRUE as 1 and FALSE as 0. So mean() of a logical column is really “how many 1s, divided by the total” — in other words, exactly the proportion of TRUE values. This shortcut is used constantly in epidemiology to compute prevalences.

6.3.4 Date variables (enrollment_date)

min(nutriheart_data$enrollment_date)   # earliest enrollment date
[1] "2020-01-13"
max(nutriheart_data$enrollment_date)   # latest enrollment date
[1] "2023-12-24"
range(nutriheart_data$enrollment_date) # both at once
[1] "2020-01-13" "2023-12-24"

Because R recognizes this column as a proper Date type (not text), it knows how to compare and order dates correctly — min() and max() work exactly as they would on numbers.

6.3.5 String variables (clinical_notes)

Free text needs its own logic, since there is no “average sentence.”

unique(nutriheart_data$clinical_notes)   # every distinct note that appears
[1] "Adheres strictly to diet." "Patient reports fatigue." 
[3] "No recent complaints."     "Sedentary lifestyle."     
table(nutriheart_data$clinical_notes)    # how often each one was written

Adheres strictly to diet.     No recent complaints.  Patient reports fatigue. 
                       38                        54                        62 
     Sedentary lifestyle. 
                       46

unique(x) lists each distinct value in x exactly once, which is a quick way to see the full range of answers hiding inside a text column before deciding how (or whether) to categorize them.

6.4 Data wrangling with dplyr

“Wrangling” means reshaping and filtering a dataframe to answer a specific question — without ever changing the original file on disk. The dplyr package (part of the tidyverse) gives us a small set of verbs that cover almost everything.

install.packages("dplyr")
library(dplyr)

We will also meet the pipe, written |>. The pipe takes whatever is on its left and feeds it in as the first argument of the function on its right. So x |> f() means exactly the same as f(x) — it just lets us chain several steps in the order we think about them, top to bottom, instead of nesting functions inside each other.

filter() keeps only the rows where the condition is TRUE. Note the double equals sign ==: it means “is equal to” (a question), while a single = is used for setting an argument’s value. Separating two conditions with a comma means “both must be true” — here, only participants who have hypertension and are 60 or older survive the filter.

6.4.5 group_by() + summarise() — the real payoff

This is where dplyr answers our actual research question: does BMI differ across diet types?

nutriheart_data |>
  group_by(diet_type) |>
  summarise(
    n_participants = n(),
    mean_bmi = mean(bmi),
    hypertension_pct = mean(hypertension) * 100
  )
# A tibble: 4 × 4
  diet_type     n_participants mean_bmi hypertension_pct
  <fct>                  <int>    <dbl>            <dbl>
1 Keto                      28     29.3             32.1
2 Mediterranean             83     28.9             32.5
3 Vegan                     35     31.8             40  
4 Western                   54     30.0             33.3
  • group_by(diet_type) does not change what is printed — it silently splits the dataframe into invisible sub-groups, one per diet type.
  • summarise() then collapses each group down to a single row, computing whatever we ask for inside it: n() counts rows per group, mean(bmi) computes the average BMI within each diet group separately, and mean(hypertension) * 100 reuses our logical-variable trick from earlier to get the hypertension prevalence, again per group.

The output is a small, four-row table — one row per diet — that is the actual, publishable answer to the NutriHeart research question stated at the beginning of this section. Every wrangling step you just learned exists to get you from 200 raw rows to a table exactly like this one.
